# Алгоритм выполнения практической работы № 3

**Тема:** настройка CI/CD. **Вариант:** калькулятор ипотеки. Рабочая папка на Windows: `D:\учеба\7 semester\Технологии внедрения программного обеспечения\Lab3`.

## Что должно получиться

После каждого `git push` в GitLab автоматически запускаются тесты. Если они прошли и push сделан в основную ветку, GitLab Runner на Linux ВМ копирует новую версию программы, перезапускает сервис и проверяет его работу. В браузере на ВМ открывается ипотечный калькулятор.

## Шаг 1. Проверить программу на своём компьютере

Откройте PowerShell и вводите команды по одной:

```powershell
cd 'D:\учеба\7 semester\Технологии внедрения программного обеспечения\Lab3'
python -m unittest discover -s tests -v
python app.py
```

Должно быть `Ran 3 tests` и `OK`. Откройте `http://localhost:8000`, введите сумму 100000, ставку 12 и срок 1 год. Ожидаемый платёж: 8884.88 ₽. Затем остановите сервер `Ctrl+C`.

## Шаг 2. Создать пустой проект в GitLab

Зайдите в GitLab.com, создайте новый **пустой** проект, например `tvpo-lab3`. Не выбирайте автоматическое создание README, чтобы проект остался пустым. Запишите адрес репозитория вида `https://gitlab.com/ЛОГИН/tvpo-lab3.git`.

## Шаг 3. Отправить локальный код

В PowerShell из папки `Lab3`:

```powershell
git init -b main
git config --local user.name "Ваше имя"
git config --local user.email "ваша почта"
git add .
git commit -m "Add mortgage calculator with tests and CI/CD"
git remote add origin https://gitlab.com/ЛОГИН/tvpo-lab3.git
git push -u origin main
```

Замените имя, почту и адрес репозитория своими. При необходимости пройдите вход в GitLab в браузере. После push проверьте, что в проекте есть `.gitlab-ci.yml`. До подключения runner задания могут иметь статус **pending** — это ожидаемо.

## Шаг 4. Подготовить Linux ВМ

ВМ должна иметь доступ к GitLab по сети. Установите на ней Python 3, curl, git и GitLab Runner по [официальной инструкции GitLab](https://docs.gitlab.com/runner/install/linux-repository/). Для Ubuntu/Debian также проверьте:

```bash
python3 --version
curl --version
git --version
gitlab-runner --version
```

В GitLab откройте **Settings → CI/CD → Runners → Create project runner**. Укажите тег `production-vm`. На ВМ выполните команду регистрации, которую покажет GitLab. Выберите executor **shell**. Не сохраняйте токен регистрации в файлах проекта. Убедитесь, что runner имеет статус **online**. Если ветка `main` защищена, runner должен быть допущен к заданиям защищённых веток.

## Шаг 5. Настроить приложение как сервис на ВМ

Передайте файл `mortgage-calculator.service` из `Lab3` на ВМ, например через общую папку ВМ или `scp`. В Linux терминале перейдите в каталог, куда передали файл, и выполните:

```bash
sudo install -d -o gitlab-runner -g gitlab-runner /home/gitlab-runner/mortgage-calculator
sudo cp mortgage-calculator.service /etc/systemd/system/
sudo systemctl daemon-reload
```

Проверьте путь к `systemctl` командой `command -v systemctl`. Он должен быть `/usr/bin/systemctl`. Если отличается, измените путь в `deploy.sh` и команде ниже. Откройте `sudo visudo -f /etc/sudoers.d/mortgage-calculator` и добавьте одну строку:

```text
gitlab-runner ALL=(root) NOPASSWD: /usr/bin/systemctl restart mortgage-calculator.service
```

Этот сервис после первого успешного развёртывания будет запускаться через job в GitLab. Чтобы он также стартовал после перезагрузки ВМ, выполните `sudo systemctl enable mortgage-calculator.service`.

## Шаг 6. Дождаться работы конвейера

Откройте в GitLab **Build → Pipelines**. После подключения runner задания `unit_tests` и `deploy_production` должны последовательно стать зелёными. Если первый pipeline остался в ожидании, запустите его повторно через интерфейс GitLab или сделайте новый commit и push.

На ВМ проверьте:

```bash
systemctl status mortgage-calculator.service
curl http://127.0.0.1:8000/health
```

Ожидаемый ответ второго запроса — `ok`. В браузере с Windows откройте `http://IP_ВМ:8000`. Для этого настройте сеть ВМ так, чтобы Windows видел её адрес и порт 8000. Если страница не открывается, сначала проверьте её внутри ВМ по `http://127.0.0.1:8000` и правила сети/брандмауэра ВМ.

## Шаг 7. Доказать автоматическое обновление

Измените заголовок `<h1>Ипотечный калькулятор</h1>` в `app.py`, например добавьте `— версия 2`. Затем в PowerShell:

```powershell
git add app.py
git commit -m "Update calculator heading"
git push
```

После зелёного pipeline обновите страницу по адресу ВМ. Новый заголовок показывает, что код автоматически обновился после push.

## Шаг 8. Показать, что тесты блокируют развёртывание

Для демонстрации временно замените в `tests/test_mortgage.py` ожидаемый платёж `8884.88` на `1.00`, сделайте commit и push. В GitLab `unit_tests` должен стать красным, а `deploy_production` не должен выполняться. Затем верните `8884.88`, снова сделайте commit и push. Итоговый pipeline должен быть зелёным.
